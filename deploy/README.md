# deploy/

Files the buildroot fork installs into the image, kept here next to the code they belong to so
that a change to occulited and its lighttpd wiring is one commit. The fork's `package/occulited`
installs them from the source archive at a pinned commit (task 2/16).

| File | Installed as | Purpose |
| --- | --- | --- |
| `lighttpd/occulited.conf` | `/etc/lighttpd/conf.d/occulited.conf` | `/api`, the shell and (B-120) all of `/addons` proxied to occulited on the loopback; `/addons` behind the gate; no XML-RPC proxies (D-29) (the shell's `Content-Security-Policy` and `Permissions-Policy` come from occulited itself, `internal/ui/csp.txt`, so they land on the shell's answers alone - openccu-lite task 259, F-5) |
| `lighttpd/occulite-gate.lua` | `/etc/lighttpd/occulite-gate.lua` | the `mod_magnet` session gate in front of `/addons/` (D-28): the SHA-256 of the id a request carries (`lighty.c.md`) and one `open()` of the file of that name in occulited's session directory — occulited names the mirror's files by the hash, never by the id (B-102) — redirect to the login otherwise. The credential is the **gate cookie** `occulite_gate` / `__Secure-occulite_gate` at `Path=/addons/` (openccu-lite task 259; the API's `occulite_session` is scoped to `/api` and never arrives here) or `?sid=` with the session id. The session's ten-character legacy alias (task 125, D-77: the CCU's `?sid=@…@` that the addon CGIs parse) is taken from `?sid=` alone, never from a cookie, and looked up in the alias directory `legacy-sessions` beside the session directory. An accepted request reaches the addon with the validated credential in `X-Occulite-Session`; a client-sent header of that name (any case, or a spelling a CGI reads as the same variable) is removed from every request first (B-94, D-65). The fork's lite `modules.conf` runs the same removal for every request the gate does not see. **An API token** (openccu-lite task 307, GitHub issue #3) opens the gate as `Authorization: Bearer <token>` when it holds the scope `addon:<id>` of the addon behind the path (or Full access): the gate hashes the secret and reads the token's file in the token mirror `gate-tokens` beside the session directory — the token's name, the URL segments it opens, its expiry and address ranges, written by occulited on every token and addon change — and answers 401 for an unknown or expired token, 403 (logged with the token's name) for another addon or an address outside the ranges. Every accepted request also carries `X-Occulite-Auth` (`session` or `token`) and, for a token, `X-Occulite-Token: <name>`; client-sent copies of both are removed like the session header's |
| `lighttpd/occulite-starting.html` | where the fork's lighttpd wiring serves it from | the waiting page while occulited does not answer (task 94): one self-contained file, generated by `npm run build` from `ui/src/starting/` with the web interface's countdown code (never edited by hand); `S50lighttpd` fills in `@HOSTNAME@`, `@VERSION@`, `@PLATFORM@` and `@IP@` with `sed` at start. Without a countdown of the web interface it says what the unit state says (task 283): restarting after a crash, a crash loop (with the journal command and the recovery hint), stopped on purpose, the system going down |
| `lighttpd/occulite-starting.lua` | `/etc/lighttpd/occulite-starting.lua` | lighttpd's answer while occulited does not answer: the waiting page for browsers, a JSON 503 for `/api/` that carries the unit state file as `unit` when it has the script's shape (task 283) |
| `systemd/occulited.service` | `/usr/lib/systemd/system/occulited.service` | the service (task 20): state in `/usr/local/etc/occulite`, journal logging, restart on failure, ordered before `addons.target`. `Type=notify` (task 122): the daemon sends `READY=1` (`internal/sdnotify`, no libsystemd) once its own server answers `/api/meta/v1/version`, so `After=occulited.service` - every addon unit - waits for an API that answers; `TimeoutStartSec=300`. `occulited-helper.service` is `Type=notify` too, ready once its socket listens. The busybox init script `S48occulited` went with task 187 (every product is systemd, D-39) |
| `systemd/occulited-unit-state` | `/usr/libexec/occulited/unit-state` (0755) | openccu-lite task 283: run as root by `occulited.service`'s `ExecStartPre=`/`ExecStartPost=`/`ExecStopPost=` (`-+`), it keeps `/run/occulite/occulited-state.json` (0644): `starting`, `running`, `restarting` after a failure, `crash-loop` (3 failures in a row, each within 120 s of its start), `stopped` on purpose (`reason` `stop` or `shutdown`), with the restart count, the failures' times and the next attempt. `occulite-starting.lua` passes it to the waiting page with its 503; occulited reads it for the `occulited-crash-loop` warning. POSIX sh, `systemctl`, `awk`, `sed`: nothing of occulited or the userfs. Tested by `go test ./internal/system -run OcculitedUnitState` with a fake `systemctl` |
| `tclrega/tclrega.c`, `tclrega/sha256.h` | `/lib/tclrega.so` | the clean-room shim that answers the addon session check (D-6), looking the session's file up by the SHA-256 of the id (B-102, its own `sha256.h`) — a 26-character session id among the sessions, a ten-character legacy alias among the aliases (task 125); built by the package with the target toolchain |

The buildroot package (`package/occulited` in the fork) builds `occulited` from a source archive
of this repository at a pinned commit and installs every file above from it — so the fork carries
no copies. The web UI (`internal/ui/dist`) is committed here for that reason: the image build must
not need Node. CI rebuilds it and fails when the committed copy is stale.

Requires `BR2_PACKAGE_LIGHTTPD_LUA` (`mod_magnet`) in the fork's defconfig and lighttpd 1.4.60 or
later: the gate uses `lighty.r.*`, because the older `lighty.request`/`lighty.env` API cannot remove
a request header, and without `lighty.r` it answers 500 rather than pass a client's
`X-Occulite-Session` on. It also needs `lighty.c.md` with SHA-256 (1.4.65 or later, built with a
crypto library) and answers 500 without it. The fork builds 1.4.82 with OpenSSL.

Tests: `lua deploy/lighttpd/occulite-gate_test.lua` runs the gate's match rules and the gate
script itself against a stand-in for `lighty.r` (Lua 5.2 or later; `docker run --rm -v
"$PWD/deploy/lighttpd:/g:ro" alpine:3.22 sh -c 'apk add -q lua5.4 && lua5.4 /g/occulite-gate_test.lua'`).
The fork's `scripts/lite-lighttpd-redirect-test.sh` runs it in a real lighttpd with the fork's
configuration: `/addons/x/` without a cookie → 302 to `/login`, and the session header against an
echo backend (cookie, `?sid=`, WebSocket over HTTP/1.1 and HTTP/2, a forged header on every path),
with the session file named as the checkout's gate looks it up. `go test ./internal/tclrega/`
compiles `sha256.h` against Go's SHA-256 and, with `OCCULITE_TCL_PREFIX` naming a Tcl 8.6
installation, loads the shim into `tclsh` against a mirror of hashed and old-style files.
